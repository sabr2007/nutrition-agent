# Решения (ADR-лог)

Формат: что выбрано → почему → альтернативы. Источники — в `docs/research/*`.

## D1. Один full-stack Next.js (TypeScript), Python — для анализа и экспорта
- **Что**: Next.js 16 (App Router) на Vercel: UI + API-роуты + цикл агента. Python-скрипт `scripts/export.py` для Parquet.
- **Почему**: один деплой и один язык рантайма, общие типы клиента и сервера, AI SDK 7 даёт готовый tool-loop, структурированный вывод и fallback-friendly вызовы; Fluid Compute держит функции до 300 с — хватает на фото-ансамбль и агент.
- **Альтернативы**: FastAPI (основной стек владельца) как отдельный сервис на Vercel Services или Cloud Run — +CORS, +второй деплой, дублирование типов; Supabase Edge Functions (Deno) — меньше экосистема для агентов. FastAPI можно добавить позже для тяжёлой аналитики, не трогая клиент.

## D2. Хостинг: Vercel + Supabase + Cloudflare Workers AI
- **Что**: фронт и API — Vercel (автодеплой из `main`, превью для веток через GitHub-интеграцию); БД/Auth/Storage/cron — Supabase; дешёвый LLM-провайдер — Cloudflare Workers AI (кредиты/бесплатная квота владельца).
- **Почему cron через pg_cron + pg_net**: на Hobby-плане Vercel Cron только раз в день; отдельный Cloudflare Worker — лишний сервис. pg_cron живёт рядом с данными, секреты в Vault, расписание в миграциях.
- **Альтернативы**: Cloudflare Worker cron (оставлен как запасной вариант: эндпоинт принимает и GET для Vercel Cron), QStash.

## D3. Клиентский PWA-shell + API, а не серверный рендер страниц
- **Что**: страницы — статический shell (prerender), данные через API с Bearer JWT и через supabase-js под RLS.
- **Почему**: офлайн-запуск с домашнего экрана (SW кэширует shell и последнюю сводку дня), совместимость с Cache Components в Next 16 (без `cookies()` в серверных компонентах), простая авторизация в standalone-PWA (хранилище PWA изолировано от Safari).
- **Альтернативы**: SSR с cookie-сессией через `proxy.ts` — хуже офлайн, сложнее кэш.

## D4. Журнал событий триггерами + версии строк
- **Что**: триггер `tg_log_event` на ключевых таблицах пишет полную строку в append-only `events`; приёмы пищи и цели — версии с `supersedes_id`.
- **Почему**: «ничего не перезаписывается без истории» гарантирует база, а не дисциплина кода; аналитику удобно строить и по снимкам, и по событиям.
- **Альтернативы**: event sourcing в коде (сложнее, легко забыть путь записи), pgaudit (шумно, без бизнес-семантики).

## D5. КБЖУ считает база, LLM только распознаёт
- **Что**: модель возвращает продукты, состояние (сырой/готовый/сухой), граммы с интервалом и уверенность по JSON-схеме; калории — `grams × per100 / 100` по базе, с отдельными строками для сырого и готового и коэффициентами привара.
- **Почему**: требование ТЗ и литература: декомпозиция «распознать → оценить массу → взять из базы» стабильнее; ошибки модели в калорийности не накапливаются (`docs/research/photo-accuracy.md`).
- **Защиты**: жиры (~900 ккал/100 г) и соусы матчатся только по явному запросу («оливки» ≠ «масло оливковое», «салат цезарь» ≠ «заправка»); один продукт дважды в прогоне склеивается.

## D6. База продуктов: USDA SR Legacy + российские таблицы + KZ-блюда с диапазонами
- **Что**: 192 базовых позиции. Цельные продукты — USDA SR Legacy (CC0, NDB-номер в `source_ref`); творог/кефир/хлеб/сметана — российские таблицы (у американских аналогов другой состав); казахские блюда — средние по лабораторным анализам стрит-фуда Алматы/Бишкека и таблице КР 2022, с честным диапазоном `kcal_low..high` и уверенностью low/medium. Штрихкоды — Open Food Facts онлайн (в КЗ ~1000 товаров, 57% с КБЖУ), найденное сохраняется в личную базу.
- **Почему**: точность там, где пользователь ест чаще всего (грудка, гречка, яйца, творог), и честность там, где состав блюда не определён.
- **Известное расхождение**: гречка у USDA 346 ккал/100 г сухой, на этикетках ЕАЭС 313–330 (другая методика углеводов). Взят USDA, на этикетку можно завести свой продукт.

## D7. Граница дня 04:00 по Asia/Almaty
- Многие ложатся после полуночи: еда в 00:30 — это ещё «вчера». Граница настраивается (0–6 ч). Проверено, что tzdata знает переход Казахстана на UTC+5 (2024).

## D8. Self-consistency и уверенность (заменено D22: один вызов ChatGPT)
- **Что**: 2 прогона vision (разные модели, если доступны), кластеризация по продукту, медиана граммов; уверенность = min(уверенность модели, согласие прогонов по энергии, качество совпадения с базой). Вопрос о порции генерируется автоматически при расхождении по калорийному продукту.
- **Факт из eval**: на моделях Workers AI ансамбль с Llama 4 Scout оказался хуже одиночной Mistral Small (MAE 165 vs 147 ккал), а уверенность модели почти не коррелирует с ошибкой. Поэтому `RECOGNITION_SAMPLES=auto`: 2 прогона только при двух здоровых сильных моделях (Gateway/OpenAI/ChatGPT), иначе 1; вес решения — на весах и вопросах. Пересчитать на сильных моделях после подключения Gateway.

## D9. Маршрутизация моделей и fallback
- **Что**: задачи `agent / strong / vision / parse / compose`; порядок провайдеров `chatgpt → gateway → openai → workers-ai`. Основная дешёвая модель после подключения Gateway — `openai/gpt-6-luna` ($0.10/$0.50 за 1M), vision — `google/gemini-3.8-flash` + `gpt-6-luna`; сейчас работают Workers AI: `qwen3.8-27b` (vision: MAE 109 ккал / MAPE 50% на Nutrition5k, ~39 с), `mistral-small-3.1` (parse и запасной vision), `gpt-oss-120b` (агент), `whisper-large-v3-turbo` ($0.0005/мин). Gateway выключен флагом `LLM_DISABLE_GATEWAY=1`: основной провайдер — Workers AI (см. D19).
- **Почему**: цена × качество × наличие доступа. Circuit breaker разделяет ошибки провайдера (квота, авторизация) и модели (невалидный JSON).
- **Нюанс Workers AI**: OpenAI-совместимый эндпоинт строже валидирует историю (пустой `content` у сообщения с tool_calls должен быть строкой) — нормализуется в `providers.ts`; без явного `maxOutputTokens` JSON обрезается.

## D10. «Войти через ChatGPT» — документированный OSS-путь, за флагом
- **Что**: локальный CLI `scripts/chatgpt-login.ts` (dynamic client registration, PKCE S256, redirect только `127.0.0.1`) → токены шифруются и уходят на сервер; сервер обновляет их с lease-lock (refresh-токены ротируются). Запросы — `/v1/responses` со `store:false`, стримом и инструментами в `namespace`. Включается `CHATGPT_PLAN_ENABLED=1`.
- **Почему**: официальная документация описывает self-serve только для open-source и локальных приложений; для удалённо хостящихся — interest form. Сценарий «self-hosted VM» (логин локально, перенос credentials) — ближайший документированный. Без реверс-инжиниринга, чужих client_id и `chatgpt.com/backend-api`.
- **Что нужно от владельца**: репозиторий уже публичный под MIT (D18); осталось отправить форму для подтверждения, выполнить локальный вход и поставить недельный лимит. См. `docs/SETUP.md`.

## D11. Агент на AI SDK 7, память и навыки в Postgres (уроки Hermes)
- **Что**: свой цикл на `generateText` + 21 инструмент; память и навыки — таблицы с версиями; детерминированная подгрузка навыка по намерению; safety-слой по признакам переедания; трейсы в `agent_runs`.
- **Почему**: Hermes показал, что работает: короткая всегда-видимая память + поиск по истории, индекс навыков с загрузкой по требованию, бесплатный SQL-гейт перед проактивным запуском, явное решение send/silent (`docs/research/hermes-lessons.md`). Слабые модели пропускают `load_skill` — поэтому роутинг по намерению.
- **Альтернативы**: Vercel eve (durable agents, skills, schedules) — интересен, но вышел после моих данных и требует согласования перед установкой; оставлен на v2.

## D12. Лимиты проактивности
- **Что**: сообщения от агента — ≤3 в день, пауза ≥2 ч, молчание после двух без ответа, тихие часы из профиля (по умолчанию 23:00–08:00). Напоминания по личному расписанию — как в ТЗ, но пропускаются, если пункт уже отмечен.
- **Почему**: исследования JITAI и усталости от уведомлений (`docs/research/habit-retention.md`) советуют ≤2 пушей в день; ТЗ просит конкретное расписание — оставил его, но с условиями и тумблерами.

## D13. Web Push в формате Declarative Web Push
- iOS показывает такие пуши без живого service worker, они не могут считаться «тихими» (3 тихих пуша → Safari удаляет подписки). TTL 1 час, `urgency: high`, `topic`. Кнопок в уведомлениях iOS нет — «отложить» живёт в приложении (`docs/research/ios-pwa-push.md`).

## D14. Дизайн «Linen terminal»
- Тёплый лён `#EFEDE4` с зерном бумаги, редакционный серифный шрифт Literata (кириллица, opsz) для заголовков, IBM Plex Mono для цифр и ASCII-элементов, системный SF Pro для текста (нативно, без загрузки). ASCII-бары с коридором цели, текстовые спарклайны, точечная «тарелка» (Stingray-референс), мягкие размытые ауры (референс UI details), чёрные pill-кнопки. Всё на токенах в `globals.css`.

## D15. CSP с `'unsafe-inline'` для скриптов
- Nonce-CSP заставил бы рендерить каждую страницу динамически и сломал бы офлайн-shell. Остальное заперто (`frame-ancestors 'none'`, `connect-src` только self + Supabase, `object-src 'none'`).

## D16. Supabase на бесплатном плане
- Лимит — 2 активных проекта на владельца. Ночью оба слота были заняты другими проектами; ставить их на паузу или включать Pro без владельца я не стал. Владелец освободил слот, и прод поднят одной командой `scripts/bootstrap-prod.sh`: проект в `eu-central-1`, миграции, закрытая регистрация, секреты cron в Vault, аккаунт, ключи в Vercel, редеплой.
- Бесплатный проект засыпает после 7 дней без запросов; cron каждые 5 минут держит его активным.

## D17. Фичи сверх списка (с обоснованием)
| Фича | Зачем | Основание |
|---|---|---|
| «Сейчас по плану» — следующий шаблон одной кнопкой на «Сегодня» | запись за 1 тап без перехода | частота записи важнее полноты (habit-retention.md: Harvey 2019, Patel 2021) |

| Честные диапазоны ккал для блюд | показывает неопределённость, а не точную ложь | ТЗ: честность в цифрах |
| Прогресс челленджа квадратиками без «стрика» | без демотивации от прерванной серии | Silverman & Barasch 2023 (habit-retention.md) |

| Итог дня в эпизодическую память без LLM | память работает даже без моделей, бесплатно | уроки Hermes |

## D18. Личные данные только в gitignored-сиде; публичный репозиторий с чистой историей
- **Что**: `bootstrap_user` больше не содержит ничего личного: цели, чек-лист, шаблоны, правила напоминаний, распорядок (тихие часы, тренировки), цифры тела и стартовая память приходят JSON-ом из `scripts/personal-seed.json` (gitignored). Чего нет в личном файле из плана, берётся из обезличенного `scripts/personal-seed.example.json`; профиль и память — никогда. Защита 1500 ккал — в check-ограничениях таблицы, а не в сиде. Перенос проверен построчно: цели, чек-лист, шаблоны и правила совпали с прежней SQL-версией.
- **Публикация**: в старой истории коммитов были личные заметки. Простой переключатель «Public» показал бы их (старые коммиты и force-push видны в Activity). Поэтому старый репозиторий переименован в приватный архив `nutrition-agent-private`, а публичный `nutrition-agent` начат с одного чистого коммита. Лицензия — MIT.
- **Альтернативы**: force-push в тот же репозиторий (история остаётся доступной по SHA и в Activity); публичное зеркало рядом с приватным основным (две копии надо синхронизировать).

## D19. Основной LLM-провайдер — Cloudflare Workers AI, Gateway — по желанию (заменено D22)
- **Что**: всё работает на Workers AI (агент `gpt-oss-120b`, фото `qwen3.8-27b`, разбор `mistral-small-3.1`, голос `whisper-large-v3-turbo`). Vercel AI Gateway выключен флагом и нужен только для скорости фото (5–10 с вместо 20–40 с) и немного точности.
- **Цена**: 10 000 нейронов в сутки бесплатно (сброс 00:00 UTC); активный день по оценке — 5–10 тысяч. При нехватке — Workers Paid $5/мес и $0.011 за 1000 нейронов сверх бесплатных. Без моделей продолжают работать шаблоны, быстрый парсер, чек-лист и напоминания по расписанию.
- **Альтернативы**: Gateway с Gemini Flash / GPT-6 Luna (нужна карта в Vercel); прямой OpenAI API (нужен ключ); ChatGPT plan (D10).

## D20. Логин без реальной почты
- **Что**: аккаунт владельца создан со служебным адресом на домене приложения. Публичная регистрация закрыта, подтверждение по почте не нужно, поэтому реальный e-mail не обязателен и не уходит во внешние сервисы без согласия. Сменить на свою почту можно в Supabase Dashboard.

## D21. Этикетки: модель переписывает, код считает и проверяет
- **Что**: фото этикетки → vision-модель только переписывает напечатанные числа по схеме (на 100 г / на порцию / масса порции / кДж / «в готовом продукте»). Пересчёт порции на 100 г, кДж → ккал, проверка калорий по Атуотеру (4/9/4, допуск 15%) и суммы БЖУ ≤ 100 г — детерминированный код (`src/lib/recognition/label.ts`). Пользователь видит цифры и предупреждения, правит и выбирает обычную порцию; продукт сохраняется в личную базу без дублей и сразу попадает в приём.
- **Почему**: ТЗ требует честных цифр. Ошибки OCR (запятая, «11,9» → «119») ловятся проверками, а не доверием модели. Личный продукт потом находят поиск, агент и шаблоны.
- **Модели**: eval на 6 синтетических этикетках — Qwen 3.8 27B 6/6 (~13 с), Llama 4 Scout 6/6 (~7 с), Mistral Small зацикливается на пробелах в JSON. Порядок: Qwen → Scout, ChatGPT/Gateway первыми, когда подключены.
- **Попутно**: Workers AI начал отвечать 400 на `reasoning_effort=low` для Mistral; параметр больше не отправляется этим моделям (`src/lib/llm/generate.ts`).
- **UX**: плитки «этикетка» и «из галереи» на экране записи (без `capture`, чтобы можно было выбрать уже сделанное фото); то же внутри «+ добавить продукт»; если штрихкода нет в Open Food Facts — «сфоткать этикетку» сохраняет продукт вместе со штрихкодом.


## D22. Только подписка ChatGPT, без запасных провайдеров (заменяет D8 и D19)
- **Что**: все вызовы моделей — агент, фото и этикетки на экране записи, разбор текста, тексты пушей, фоновый разбор памяти — идут в план ChatGPT («Войти через ChatGPT»). Одна модель на задачу (`src/lib/llm/models.ts`): чат и агент — `gpt-6-luna` (effort low), «Думать дольше» — `gpt-6.1-sol` (effort high), фото и этикетки — `gpt-6.1-terra`, разбор текста и пуши — `gpt-6-luna`. Ни fallback-цепочек, ни circuit breaker, ни ансамбля из нескольких прогонов на фото: один вызов, ошибка — понятное сообщение в интерфейсе и кнопка «Повторить». Удалены Vercel AI Gateway, OpenAI API-ключ и Workers AI как LLM-провайдеры, их зависимости, `LLM_PROVIDER_ORDER`, `LLM_DISABLE_GATEWAY`, `RECOGNITION_SAMPLES`, eval-харнессы фото и этикеток под модели Cloudflare.
- **Почему**: владелец подключил подписку и не хочет, чтобы что-то работало мимо неё; качество GPT-6 выше, чем у open-weight моделей Cloudflare (фото 20–90 с → один вызов), а запасные цепочки усложняли код и маскировали проблемы.
- **Исключение — голос**: у плана ChatGPT нет транскрипции и аудио-входа (OpenAI исключает их явно, `docs/research/chatgpt-oauth.md` §3.1), а встроенное распознавание речи iOS не работает в приложении с экрана «Домой» (WebKit bug 225298). Поэтому только расшифровка голоса идёт в Whisper на Cloudflare Workers AI (бесплатная квота, одна модель, без запасных). Если голос не нужен — переменные `CLOUDFLARE_*` можно удалить: кнопка микрофона ответит «расшифровка недоступна», останется диктовка с клавиатуры iPhone.
- **Что будет при исчерпании лимита подписки**: чат, фото и разбор текста ответят «Лимит подписки ChatGPT исчерпан»; шаблоны, быстрый парсер («грудка 250»), ручная запись, чек-лист и напоминания по расписанию (текст из шаблона правила) работают без моделей.
- **Проверка**: `POST /api/providers/chatgpt/check` (владелец или cron-секрет) — каталог моделей аккаунта, пробы текста, reasoning effort, structured output, инструментов в namespace и картинки, а с `{"agent": true}` — сценарии агента в dry-run (без записи данных).
- **Альтернативы**: оставить Cloudflare запасным (так было в D19) — против прямого желания владельца; OpenAI API-ключ для голоса — платно и ещё один ключ.

## D23. Главный вход — чат, повторяющий ChatGPT
- **Что**: вкладка «Коуч» стала «Чат» (`/chat`, старый `/coach` редиректится). Экран чата — копия поведения ChatGPT по записи экрана владельца: таб-бар скрыт, сверху круглая кнопка меню (разделы приложения) и пилюля «Чат | ккал за день»; поле «Спроси Рядом» с «+» слева и микрофоном справа, стрелка отправки появляется, когда есть текст или фото. «+» открывает меню: Камера, Фото (до 4 штук), Навыки (быстрые сценарии), «Думать дольше» с галочкой и чипом в поле. Фото встают миниатюрами над полем с крестиком и грузятся в приватный бакет сразу. Микрофон: полоска записи с крестиком, живой волной из точек, ■ (вставить текст в поле) и ↑ (расшифровать и сразу отправить); во время расшифровки ■ превращается в спиннер. Кнопку голосового агента ChatGPT не переносили (по просьбе владельца).
- **Агент видит фото сам**: картинки передаются агенту как вход; еду он записывает через `log_meal` (КБЖУ по-прежнему считает база), этикетку — новым инструментом `save_label_food` (модель переписывает цифры, `normalizeLabel` пересчитывает и проверяет) и затем `log_meal`, вес с весов — `log_body_metric`. Приём из фото получает `input_method = 'photo'` и строку в `recognitions` со ссылкой на `media` — цепочка «сырое фото → распознавание → приём» сохраняется, как на экране записи.
- **Всё записанное видно**: под ответом — карточки «в дневнике» (ссылка на правку приёма) и чипы других записей (вес, чек-лист, напоминание, рецепт, продукт, память); «Сегодня» обновляется после каждого ответа, пилюля в шапке показывает калории дня.
- **Стрим**: `/api/chat` отдаёт NDJSON — статус инструмента («Записываю приём…»), текст по мере генерации, затем сохранённые сообщения. Ход агента дорабатывает в `after()`, даже если закрыть приложение; при обрыве связи клиент сначала ищет сохранённый ответ и только потом предлагает «Повторить».
- **Таб-бар** уменьшен: 58 px вместо 76, «+» 44 px внутри панели вместо 68 px, торчащего наружу.
- **Ограничение веба**: PWA не может показать свою сетку галереи прямо в поле, как нативный ChatGPT, — «Фото» открывает системный выбор фото iOS; всё остальное (меню, миниатюры, крестики, стрелка, запись голоса) повторено.

## D24. Продукт, которого нет в базе: не подставлять похожий, а спросить или записать цифры человека
- **Случай из прода (24.11, прогоны `2e41e53b…`–`bd1446c6…`)**: «Fuse Tea 0,5 л, там 170 ккал» → `log_meal(query "Fuse Tea")` молча взял «Чай без сахара» (5 ккал: `searchFoodsSmart` при пустом ответе ищет по отдельным словам, «tea» совпало с `name_en` «Tea, brewed»), потом запрос «сладкий холодный чай…» совпал с алиасом «сладкий картофель» → «Батат» 500 г = 430 ккал с названием «Fuse Tea 0,5 л (170 ккал)»; `edit_meal` с выдуманным `food_id` упал, удаление своей ошибки требовало кнопки, Fuse Tea так и не записался.
- **Что сделано**:
  1. **Гейт релевантности** (`src/lib/recognition/relevance.ts`) между поиском и записью: бренд (латиница, «кавычки», известные бренды, явный `brand`) матчится только на продукт с этим брендом или личный, никогда на общий; напитки — только на напитки/молочное; score ≥ 0.75; каждое существительное запроса должно быть существительным продукта или алиаса (сравнение по основе до окончания: «грудки» ≈ «грудка», но «варенье» ≠ «варёные»); значимое прилагательное («сладкий», «манная») — тоже; главное слово продукта должно быть в запросе («шашлык из грудки» ≠ «грудка»), кроме полного совпадения с алиасом; «с X» должен быть в продукте (иначе — отдельной позицией), противоречия «с сахаром»/«без сахара», «на молоке»/«на воде» отсекаются. При равном score обычный вариант важнее «без X», о котором не просили (кола, а не кола без сахара). Если гейт не прошёл — повторный поиск по словам продукта («2 яйца» → «яйца») с той же проверкой. Попутно: орехи больше не отсекаются защитой «жиры только по явному запросу».
  2. Слабое совпадение → **ничего не записано**, `log_meal` возвращает `{ status: 'needs_food', needs: [{ query, reason, candidates }], resolved }`; приём из нескольких позиций не пишется частично. Общий аналог бренда — только если человек выбрал его кнопкой (`allow_generic`).
  3. **Название приёма собирает код** из позиций (`src/lib/agent/meal-title.ts`); название агента принимается, только если в нём нет цифр и калорий и каждое слово-продукт есть в составе (или это «Обед», «Перекус»…).
  4. **`save_user_food`**: продукт с цифрами человека (или с этикетки / из веба с URL). Код пересчитывает на 100 г, для мл 1 мл = 1 г, штука без веса = 100 г условно (видно в заметке), проверяет Атуотер (если даны все БЖУ; расхождение > 15% — переспросить, `confirm_mismatch`), сумму БЖУ ≤ 100 г и ≤ 900 ккал/100 г. Можно только ккал: БЖУ = null, `confidence = 'user_kcal_only'`, в позиции приёма `per100.partial`, итоги дня считают их как 0 и показывают «БЖУ неполные». Одна активная строка на имя + бренд: те же цифры — переиспользуется, новые — старая архивируется (история в `events`), новая создаётся.
  5. **`edit_meal`** заменяет позицию на `food_id` (`replace: [{ item, food_id, grams? }]`), пересобирает название и **перечитывает приём из базы**: агент называет `in_database_now`, а не намерение. **`delete_meal`**: приём, который агент сам записал в чате за последние 30 минут (корень версии с `client_id agent:*`), удаляется сразу — откат своей ошибки; старше или чужой — по кнопке, как раньше. Правка (новая версия) — без кнопки, как и была.
  6. Промпт (`agent-v4`): «назвал калорийность → `save_user_food`, а не поиск похожего», «бренд → `brand`», «`needs_food` → спроси кнопками», «исправь / висит → `edit_meal` по id из снимка дня, без нового `log_meal`»; в снимке дня у приёмов есть id и состав. Детерминированные подсказки: `isCorrection`, `statesCalories`.
- **Схема** (`20261126000100_user_foods.sql`): БЖУ в `foods` nullable, `confidence` + `user_kcal_only`, уникальный индекс (user_id, имя, бренд) для активных `user`/`web`, `foods` в журнале событий, `search_foods` отдаёт `aliases`.
- **Проверка**: калибровка на 190 типичных запросах против прод-поиска — 147 совпали верно, 43 честно вернули `needs_food` (нет в базе, бренд, «с X»), ни одной подмены; unit-тесты на гейт (включая все найденные ложные совпадения), `save_user_food` (мл→г, только ккал, дедуп) и названия; eval-сценарии `fuse_tea_kcal`, `unknown_bar_no_numbers`, `fix_kcal_same_meal`, `brand_vs_generic` в dry-run с «сухим миром» (`src/lib/agent/dry-world.ts`), где записи и правки агента видны проверкам.
- **Альтернативы**: только поднять порог score — не ловит «Fuse Tea» (score 0.95 через `name_en`) и «варенье» (1.34); эмбеддинги — дороже, непрозрачно и вне плана ChatGPT; спрашивать про каждый продукт — трение. Запомнить выбор «Coca-Cola = кола с сахаром», чтобы не спрашивать снова, — следующий шаг (личный алиас).

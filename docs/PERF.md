# Производительность Mini App и API

Цели v2 (mobile, 4G): LCP < 1,5 с, INP < 150 мс, CLS < 0,05; JS первой загрузки «Сегодня» < 150 KB gzip; `/api/today` p95 < 300 мс; переключение вкладок и дней — визуально мгновенно (< 100 мс), без экрана «загрузка», если данные уже были.

### Что видно
- **Функции Vercel в `iad1` (Вашингтон), база — `eu-central-1` (Франкфурт).** Каждый запрос к БД пересекает Атлантику (~90 мс), а `/api/today` делает 4 последовательных похода (проверка токена → профиль → пачка запросов дня → шаблоны/сообщения). Сам SQL — 12 мс. Перенос функций в `fra1` — главная мера.
- **supabase-js целиком в клиенте — 62,5 KB gzip** (GoTrue, PostgREST, Realtime/phoenix), хотя клиенту нужна только сессия: все данные идут через наш API.
- Экран «Сегодня» без кэша показывает «загрузка» на весь экран; `refreshInterval: 60_000` + `revalidateOnFocus` — опрос вместо событий.
- `noModule`-полифилы (38,5 KB) современные браузеры не грузят; «legacy JavaScript» ещё ~14,6 KB.
- Шрифты Literata и IBM Plex Mono — через `next/font` (subset latin + cyrillic, `display: swap`).

### Что сделано и что дало
| Мера | Эффект |
|---|---|
| Функции Vercel `iad1` → **`fra1`** (`vercel.json`), рядом с базой во Франкфурте | `/api/today` p50 1 028 → 214 мс сразу; дальше — два похода в базу вместо четырёх |
| `/api/today`: проверка профиля слита с чтением профиля, убраны запросы «последнее сообщение» и «уведомление» (в Mini App нет карточки коуча); день и шаблоны — параллельно; `Server-Timing` | p50 214 → 181 мс, p95 714 → 280 мс |
| **supabase-js убран из общей оболочки**: сессия читается и обновляется напрямую (тот же ключ localStorage и тот же Web Lock, что у supabase-js), supabase-js грузится только на страницах, которые пишут в таблицы | −62 KB gzip на «Сегодня» и «Ещё» |
| «Сегодня» без SWR: свой маленький хук дня (память → кэш устройства → сеть), обновление при возврате в приложение и по событию вместо опроса раз в минуту | −5 KB; нет фоновых запросов каждые 60 с |
| Кэш дней на устройстве (10 последних) + предзагрузка соседнего дня | знакомый день и «вчера» — без экрана «загрузка» |
| Оптимистичное удаление приёма (цифры дня меняются сразу, откат при ошибке) | правка ощущается мгновенной |
| Офлайн-очередь (IndexedDB) и пуш-переподписка — по требованию | −0,8 KB с первой загрузки |
| Внутри Telegram: без `mix-blend-mode` на всю страницу, без бесконечной анимации размытой «ауры», без `backdrop-filter` под таб-баром | меньше перерисовок на скролле в iOS webview (замерить на телефоне — после привязки) |
| Шрифты: Literata и IBM Plex Mono через `next/font` (subset latin + cyrillic, `display: swap`) — проверено, без изменений | — |
| Чат и экран записи: отдельные маршруты, в первую загрузку «Сегодня» не попадают; `zxing_reader.wasm` грузится только на экране записи | — |
| Service worker: версия = коммит деплоя, старые кэши чистятся, страница один раз перезагружается | Mini App не застревает на старой оболочке |

### Индексы (`EXPLAIN ANALYZE` в проде)
- Приёмы дня: `Index Scan using meals_day on meals` (user_id, local_day), выполнение 0,15 мс.
- Позиции приёмов: `Index Scan using meal_items_meal on meal_items`, выполнение 0,09 мс.
- Узкое место было не в SQL (≈12 мс на всё), а в расстоянии между функциями и базой.

### Что осталось
- Холодный LCP на Slow 4G — 1,1–3,7 с: ~70 KB React DOM + 44 KB рантайма Next.js не уменьшить без смены стека; в Telegram это первый запуск, дальше статика из кэша service worker, а день — из кэша устройства.
- Переключение вкладок в iOS Telegram и плавность скролла — замерить на телефоне после привязки бота.

# Архитектура «Рядом» (v1)

Личный AI-агент по питанию: PWA на iPhone, агент с памятью, инструментами и проактивностью.
Схема данных мультипользовательская с первого дня (RLS на всех таблицах), продукт — для одного пользователя.

```
 iPhone (PWA, standalone)                       Vercel (Next.js 16, Fluid Compute, Node)
┌──────────────────────────┐   HTTPS+JWT   ┌──────────────────────────────────────────────┐
│ Сегодня · Записать ·     │──────────────▶│ /api/today        сводка дня (1 запрос)      │
│ Коуч · Тело · Ещё        │               │ /api/meals*       сохранение версий приёма   │
│ service worker:          │               │ /api/recognize/*  фото / голос / текст        │
│  · офлайн shell + кэш    │               │ /api/chat         цикл агента (21 инструмент) │
│  · IndexedDB outbox      │◀── push ──────│ /api/cron/tick    правила напоминаний + агент │
│  · Declarative Web Push  │               │ /api/export       ZIP с CSV всех таблиц       │
└──────────┬───────────────┘               └───────┬───────────────┬──────────────────────┘
           │ supabase-js (RLS)                     │ service role  │ LLM router (fallback,
           ▼                                       ▼               ▼  circuit breaker, cost log)
┌──────────────────────────────────────────────────────┐   ┌─────────────────────────────────┐
│ Supabase: Postgres 17 + Auth + Storage + pg_cron     │   │ 1. ChatGPT plan (OAuth, opt-in) │
│ · append-only events (триггеры на всех таблицах)     │   │ 2. Vercel AI Gateway (OIDC)     │
│ · meals/meal_items с версиями (supersedes_id)        │   │ 3. OpenAI API key               │
│ · foods (USDA SR, RU-таблицы, KZ-блюда с диапазонами)│   │ 4. Cloudflare Workers AI        │
│ · memories / skills (версии) / agent_runs / llm_calls│   └─────────────────────────────────┘
│ · pg_cron ── pg_net ──▶ /api/cron/tick каждые 5 мин  │
│ · private bucket `media` (фото, аудио)               │
└──────────────────────────────────────────────────────┘
```

## Слои кода

| Расчёты | `src/lib/nutrition/*` | детерминированный КБЖУ, сырой↔готовый вес, граница дня (unit-тесты) |
| Доступ к данным | `src/lib/data/*` | профиль, цель на дату, сводка дня, сохранение приёма (пересчёт на сервере), шаблоны |
| Распознавание | `src/lib/recognition/*` | промпты (версии), JSON-схема, быстрый парсер, сопоставление с базой, self-consistency |
| LLM | `src/lib/llm/*` | маршруты по задачам, fallback, circuit breaker, цены, логирование, транскрипция, ChatGPT OAuth |

## Данные и история

- **Ничего не перезаписывается без следа.** Каждая вставка/обновление в ключевых таблицах пишется триггером в `events` (append-only: у пользователей нет UPDATE/DELETE на эту таблицу). Payload — полная строка.
- **Приёмы пищи версионируются**: правка = новая строка с `supersedes_id`, `version+1`, старая получает `is_current=false`; удаление = версия со `status='deleted'`. Атомарно через RPC `save_meal` / `delete_meal` (security invoker → RLS).
- **Сырые входы**: фото/аудио в приватном bucket (`<user_id>/<kind>/<date>/<uuid>`), строка в `media` (sha256, размер, размеры, длительность). Полный JSON каждого прогона модели — в `recognitions.runs` (модель, провайдер, латентность, токены, стоимость), агрегат — в `recognitions.result`.
- **Правки модели** → `meal_corrections` (граммы модели → подтверждённые). Отсюда персональная калибровка (медиана отношений со сглаживанием к 1) и few-shot в промпте.
- **Метрика трения**: `meals.time_to_confirm_ms`, `logged_at` отдельно от `eaten_at`, `input_method`.
- **Время**: всё в `timestamptz` (UTC). `local_day` = дата в `Asia/Almaty` для `(t − граница дня)`, граница по умолчанию 04:00 (еда в 00:30 — это ещё вчера). Функция `user_local_day()` в БД и `localDay()` в TS дают одинаковый результат (тесты).
- **Цели** иммутабельны: изменение = новая версия; на каждую дату берётся действующая. В БД `check (kcal_floor >= 1500)` и `kcal_min >= kcal_floor`.

## Распознавание (фото / голос / текст)

1. **Текст**: быстрый парсер без LLM для простых записей («грудка 250», «3 яйца, творог 200») — 15–50 мс; иначе LLM (`parse`) со структурированным выводом.
2. **Голос**: MediaRecorder (`audio/mp4` на iOS) → Storage → транскрипция (Gateway `openai/gpt-transcribe` → OpenAI → Workers AI `whisper-large-v3-turbo`) → текстовый пайплайн.
3. **Фото**: ресайз на клиенте (≤1280px JPEG) → Storage → N прогонов vision-модели (по умолчанию 2, разные модели при наличии) → кластеризация одинаковых продуктов между прогонами → медиана граммов, «присутствие», разброс → уверенность. Режим «на весах»: число с экрана весов = граммы.
3a. **Этикетка**: фото из галереи или камеры (≤2048px, для мелкого шрифта) → vision-модель только переписывает напечатанные цифры (`label-v1`, порядок Qwen → Llama 4 Scout) → `normalizeLabel`: «на порцию» → на 100 г, кДж → ккал, проверка по Атуотеру и суммы БЖУ → пользователь сверяет цифры и порцию → личный продукт (`foods.source = 'label'`, без дублей; штрихкод сохраняется, если Open Food Facts его не знал) → приём (`input_method = 'label'`). Сырой ответ модели — в `recognitions` (kind `label`).
4. **Модель только распознаёт** (продукт, состояние, граммы с интервалом, видимый жир, уверенность, 0–2 вопроса с эффектами). КБЖУ считается детерминированно по базе (`grams × per100 / 100`), с защитой от опасных совпадений (жиры и соусы только по явному запросу).
5. Уточняющие вопросы — кнопки с эффектом (`set_grams`, `add_item`, `remove_item`); если модели расходятся по калорийному продукту, вопрос о порции генерируется автоматически.

## Агент

- **Цикл**: AI SDK 7 `generateText` + инструменты, `stopWhen: isStepCount(8)`; для ChatGPT-плана — `streamText` и инструменты в `namespace`.
- **Системный промпт** (Hermes-подход): идентичность и тон → правила → жёсткая безопасность → закреплённая память → паттерны и недавние итоги → релевантная память (FTS по запросу) → индекс навыков → снимок дня (цель, съедено, остаток, чек-лист, челлендж) → активный навык (детерминированный роутинг по намерению) → safety-блок (признаки переедания).
- **Инструменты** (типизированные, zod): `get_day_summary`, `list_templates`, `search_foods`, `log_meal`, `edit_meal`, `delete_meal`*, `update_checklist`, `log_body_metric`, `log_slip`, `get_trends`, `suggest_meal_for_remaining_macros`, `generate_recipe`, `make_shopping_list`, `schedule_reminder`, `update_goal`*, `remember_fact`, `search_memory`, `get_calendar_context`, `load_skill`, `ask_user`, `send_message`. (*) — только через кнопку подтверждения (`/api/agent/confirm`).
- **Память**: `memories` (fact / preference / pattern / routine / episode / day_summary / week_summary), статусы `proposed → active/rejected/archived`, закрепление, версии через `supersedes_id`, FTS (`russian`). Видна и редактируется на экране «Память». Итог дня пишется детерминированно на смене суток.
- **Навыки**: процедуры в Markdown в таблице `skills` с версиями (`slip_review` уже v2), личные форки перекрывают системные.
- **Трейсы**: `agent_runs` (триггер, навык, модель/провайдер, шаги, вызовы инструментов с превью результатов и ошибками, токены, стоимость, латентность, решение sent/silent) + `llm_calls` на каждый вызов модели (включая неудачные попытки и fallback).

## Проактивность

`pg_cron` каждые 5 минут → `pg_net` POST `/api/cron/tick` (Bearer-секрет из Vault). Тик для каждого пользователя:
1. доставляет отложенные уведомления (snooze, `schedule_reminder` агента);
2. на смене суток пишет итог вчерашнего дня в память (без LLM);
3. проверяет правила (`reminder_rules`: время + окно, дни, только тренировочные дни, JSON-условие на фактах дня, кулдаун, раз в день) — бесплатный гейт до LLM;
4. текст: шаблон с подстановкой, либо LLM-формулировка (`compose`), либо полноценный запуск агента в проактивном режиме (`kind='agent'`), который сам решает писать или молчать;
5. лимиты для сообщений агента: тихие часы, ≤3 в день, пауза ≥2 ч, молчание после 2 сообщений без ответа. Напоминания, которые пользователь сам настроил, этим лимитом не режутся (но уважают тихие часы и пропускаются, если пункт уже сделан).
Реакции (opened / snoozed / done / dismissed) пишутся в `notifications`.

## LLM-провайдеры

`src/lib/llm/providers.ts` — маршруты по задачам (`agent`, `strong`, `vision`, `parse`, `compose`), порядок провайдеров из `LLM_PROVIDER_ORDER` (по умолчанию `chatgpt → gateway → openai → workers-ai`). Ошибки классифицируются (quota/auth/rate/server/timeout/bad_request): провайдерные — выключают провайдер на время (circuit breaker), модельные — только модель. Каждый вызов (успех и провал) — в `llm_calls` с токенами и стоимостью по таблице цен.

## Безопасность

- RLS на всех пользовательских таблицах (`user_id = auth.uid()`), `anon` без прав, токены провайдеров — только service role, зашифрованы AES-256-GCM.
- Публичная регистрация выключена, пароль ≥ 12 символов, аккаунт создаётся Admin API.
- Секреты только в env (Vercel) и Vault (Supabase); в репозитории — `.env.example`. Все личные данные (цифры тела, распорядок, цели, шаблоны, правила напоминаний, стартовая память) — только в `scripts/personal-seed.json` (gitignored); в репозитории — обезличенный пример `scripts/personal-seed.example.json`.
- CSP, `frame-ancestors 'none'`, HSTS, `nosniff`, Permissions-Policy (камера/микрофон только self). Логи без персональных данных.
